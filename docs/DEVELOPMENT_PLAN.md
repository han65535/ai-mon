# AI Mon 개발 기획서

- 작성일: 2026-09-10
- 상태: 로컬 사용량 MVP 구현; 실제 검증 범위는 `BUILD_AND_RELEASE.md` 참고
- 가칭: AI Mon
- 방향: C++ 기반 Windows 네이티브 AI 사용량 모니터

## 1. 목표와 전제

구현 기록(2026-09-10): C++17 트레이 UI, 두 제공자 수집, 증분 감시, 설정 및 캐시 복구를 구현했다. 캐시와 체크포인트는 원자적 교체가 가능한 하나의 `state.json`으로 통합했다. 아래 성능·호환성 표의 값은 목표이며, 실제 측정과 미검증 항목은 [빌드 및 검증 기록](BUILD_AND_RELEASE.md)에 별도로 정리한다.

추가 요청 반영: 현재 사용자용 MSI 설치 패키지를 제공한다. 설치 패키지도 1MB 이내이며 설치·복구·제거 및 사용자 데이터 보존을 검증했다. 상세 내용은 [설치 패키지 문서](INSTALLER.md)를 참고한다.

0.2.0 글로벌 사용자 지원: 한국어·영어 JSON을 EXE에 내장하고 설정에서 즉시 전환한다. 기본값은 Windows 표시 언어 자동 감지이며 미지원 언어는 영어로 표시한다. 사용자 데이터 폴더의 외부 JSON 언어팩도 발견·선택할 수 있고, 번역 누락 항목은 영어로 대체한다. 영문·한국어 설치 마법사와 README를 제공한다. 규격과 확장 방법은 [언어팩 문서](LOCALIZATION.md)를 참고한다.

AI 개발도구의 사용량을 작업 중 빠르게 확인할 수 있는 가벼운 트레이 앱을 만든다. 상용 개발툴 구매나 설치 없이 개발하고, 사용자는 별도 설치 과정 없이 실행할 수 있어야 한다.

| 항목 | 기준 |
| --- | --- |
| 대상 사용자 | Windows에서 AI 코딩 도구를 사용하는 개발자 |
| 운영체제 | Windows 10 및 Windows 11 |
| 초기 아키텍처 | x64; ARM64 네이티브 빌드는 후속 검토 |
| 개발 언어 | C++17 |
| UI | Win32 기본 컨트롤과 GDI |
| 배포 | `ai-mon.exe` 포터블 및 단일 MSI 설치 패키지 |
| 크기 상한 | 압축 전 최종 EXE 1,000,000바이트 이하 |
| 실행 의존성 | Windows 기본 구성요소만 사용; 추가 런타임 설치 불필요 |
| 실행 권한 | 일반 사용자 권한 |
| 데이터 처리 | 로컬 우선; 초기 버전은 앱 자체의 외부 통신 없음 |

크기 기준은 개발도구, 소스, 별도 디버그 심볼, 실행 후 생성되는 설정 및 캐시를 제외한다. 필수 부속 파일이 생기면 그 크기도 배포 예산에 포함한다. 법적 고지 등 필요한 텍스트는 가능하면 EXE의 정보 화면에 포함한다. 추후 서명할 경우 서명 후 크기를 기준으로 검사한다.

Windows 10의 세부 최소 빌드는 실제 API 사용과 실행 검증을 통해 0단계에서 확정한다. 지원하지 않는 최신 API는 동적 탐색 및 대체 경로를 제공하거나 사용하지 않는다.

회사에서 승인된 포터블 도구의 반입과 실행이 가능하다고 가정한다. 포터블 사용도 제한되는 경우 기존 승인 도구로 빌드할 수 있는지 별도로 확인한다. 본 문서는 도구 설치나 다운로드를 수행하지 않는다.

## 2. 첫 버전의 제품 범위

초기 제공자는 참고 프로젝트의 주요 사용 사례를 따라 Claude Code와 Codex로 가정한다. 실제 지원 버전과 입력 형식은 개발 착수 시 확인한다. 제공자 연동 가능성을 검증하기 전에는 모든 사용량 또는 모든 계정 한도를 표시할 수 있다고 약속하지 않는다.

### MVP 필수 기능

| 기능 | 동작 및 완료 기준 |
| --- | --- |
| 트레이 상주 | 실행 시 아이콘 등록, 클릭 시 요약창, 우클릭 시 메뉴 |
| 사용량 요약 | 제공자별 오늘의 입력·출력 토큰과 마지막 수집 시각 표시 |
| 로컬 수집 | 검증한 로컬 데이터에서 사용량 필드만 읽어 집계 |
| 제공자 설정 | 제공자별 활성화, 자동 경로 탐색, 사용자 지정 경로 |
| 수집 상태 | 정상, 수집 중, 데이터 없음, 경로 없음, 읽기 실패, 지원하지 않는 형식 구분 |
| 증분 갱신 | 변경된 파일과 새로 추가된 구간을 우선 처리 |
| 상태 복구 | 재시작 후 동일 이벤트를 중복 합산하지 않음 |
| 수동 새로고침 | 자동 갱신과 별도로 사용자가 갱신 요청 가능 |
| 기본 설정 | 갱신 주기, 시작 시 요약창 표시 여부 |
| 종료 | 감시 및 작업을 정리하고 트레이 아이콘 제거 |

캐시 토큰과 모델별 사용량은 원본에 의미가 확인된 필드가 있는 경우 지원한다. 입력 토큰과 캐시 토큰이 중첩되는지 제공자별로 확인하며, 의미가 다른 항목을 무조건 더하지 않는다.

## 3. 사용량의 의미와 표시 원칙

토큰 사용량과 구독 계정의 남은 한도는 다른 지표다. 로컬 토큰 합계로 계정의 남은 비율을 역산하지 않는다. 참고 프로젝트 역시 로컬 사용량과 제공자 한도를 구분한다. [WhereMyTokens 개요](https://github.com/jeongwookie/WhereMyTokens)

| 지표 | 의미 | 표시 원칙 |
| --- | --- | --- |
| 로컬 사용량 | 읽을 수 있었던 로컬 기록에 포함된 토큰 | `이 PC에서 수집한 사용량`으로 범위 명시 |
| 계정 한도 | 서비스가 보고한 특정 범위와 기간의 한도 | 출처, 측정 시각, 초기화 시각 함께 표시 |
| 비용 추정 | 토큰과 특정 시점의 API 가격표로 계산한 값 | 실제 청구액과 구분하고 가격 기준일 표시 |

- 값이 없으면 `확인 불가` 또는 `데이터 없음`으로 표시한다. 0이나 무제한으로 대체하지 않는다.
- 수집 실패 시 기존 값을 보존하되 갱신 실패와 마지막 성공 시각을 표시한다.
- 첫 인덱싱 중에는 `수집 중`으로 표시하여 부분 합계를 완전한 합계로 오해하지 않게 한다.
- 날짜 경계는 사용자 Windows 시간대를 기준으로 한다. 원본 시각과 내부 저장은 UTC를 사용한다.
- 시간대가 바뀌면 보존 중인 이벤트를 재집계한다. 시간대 정보가 없는 원본은 해석 규칙을 기록한다.
- 다른 PC, 웹 채팅, 삭제된 기록 등 수집 범위 밖의 사용량은 포함되지 않을 수 있음을 요약창에서 확인할 수 있게 한다.

## 4. 개발환경과 기술 선택

| 영역 | 선택 | 구현 방향 |
| --- | --- | --- |
| 컴파일러 및 링커 | LLVM-MinGW UCRT x64, Clang/LLD | 포터블 릴리스의 버전과 체크섬 고정 |
| 편집기 | 기존 승인 편집기 또는 VS Code ZIP | IDE에 종속되지 않는 빌드 |
| 빌드 진입점 | `scripts/build.ps1` | Debug, Release, Test 구성 |
| 디버깅 | 선택한 도구 묶음의 LLDB 등 | 0단계에서 중단점·스택 확인까지 검증 |
| 창과 컨트롤 | Win32 Unicode API | 기본 버튼, 목록, 메뉴 및 대화상자 |
| 트레이 | `Shell_NotifyIconW` | Explorer 재시작 후 아이콘 재등록 |
| 그리기 | GDI | 최소한의 사용자 지정 그리기, 시스템 폰트 사용 |
| 파일 변경 감지 | `ReadDirectoryChangesW` | 작업 스레드에서 처리, 누락 시 재탐색 |
| JSON 처리 | 소형 C/C++ 파서 1개 | 정확성·라이선스·빌드 크기를 비교해 0단계에서 확정 |
| 설정 및 캐시 | 버전이 있는 UTF-8 JSON/JSONL 파일 | 임시 파일 기록 후 교체 |
| 향후 HTTPS | WinHTTP | 연결·응답 제한과 프록시 동작 검증 |

LLVM-MinGW는 압축을 풀어 사용할 수 있는 Windows 도구 묶음을 제공하고 UCRT는 Windows 10부터 기본 제공된다. C++ 표준 라이브러리 등 추가 지원 라이브러리는 별도 DLL이 필요하지 않도록 링크 구성을 검증한다. [LLVM-MinGW 공식 설명](https://github.com/mstorsjo/llvm-mingw#releases)

VS Code는 Windows ZIP 배포본에서 포터블 모드를 지원한다. 회사에서 이미 사용하는 편집기가 있으면 그대로 사용한다. [VS Code 포터블 모드](https://code.visualstudio.com/docs/setup/portable)

### C++ 사용 규칙

- RAII로 파일, 스레드, 이벤트 및 GDI 핸들의 수명을 관리한다.
- 필요한 범위에서 `std::string`, `std::vector`, `std::optional` 등을 사용한다.
- 대형 템플릿 라이브러리, 정규식, 스트림 포맷팅은 도입 전에 크기를 측정한다.
- 예외와 RTTI를 처음부터 일괄 제거하지 않는다. 크기 측정 후 사용 여부 및 오류 처리 정책과 함께 결정한다.
- 파서는 숫자 오버플로, UTF-8, JSON 이스케이프, 최대 깊이 및 최대 레코드 크기를 처리해야 한다.
- Windows API 경계는 UTF-16, 파일과 제공자 데이터 경계는 UTF-8로 정한다.
- 크기를 줄이기 위해 기본 메모리 보호나 검증을 제거하지 않는다.

## 5. 화면과 사용 흐름

1. 사용자가 `ai-mon.exe`를 실행한다.
2. 중복 실행이면 기존 창을 활성화하고 새 프로세스는 종료한다.
3. 첫 실행은 요약창을 열고 탐색된 제공자와 데이터 상태를 보여준다.
4. 이후 실행은 설정에 따라 트레이에서 시작한다.
5. 트레이 클릭으로 요약창을 열고 제공자별 사용량을 확인한다.
6. 닫기 버튼은 창을 숨기고, 트레이 메뉴의 종료는 앱을 종료한다.

요약창 개념 예시이며 실제 수치는 아니다.

```text
AI Mon                         오늘

Claude Code
입력 123,456   출력 12,345
정상 · 10초 전 갱신

Codex
입력 234,567   출력 23,456
정상 · 10초 전 갱신

이 PC에서 수집한 사용량
[새로고침]                 [설정]
```

트레이 메뉴는 `열기`, `새로고침`, `설정`, `정보`, `종료`로 구성한다. 데이터 수집에 대한 내부 구현 용어는 사용자 화면에 노출하지 않는다.

기본 컨트롤의 키보드 탐색과 고대비 모드를 유지한다. 100%, 150%, 200% 배율과 모니터 간 이동을 검증하고, 다크 테마의 사용자 지정 구현은 후순위로 둔다.

## 6. 내부 구조

```text
제공자별 로컬 데이터
        ↓
경로 탐색 / 변경 감지
        ↓
제공자 어댑터 → 공통 사용량 이벤트
        ↓
중복 제거 / 기간 집계 / 캐시
        ↓
화면용 스냅샷
        ↓
Win32 요약창 / 트레이
```

| 모듈 | 책임 |
| --- | --- |
| `app` | 시작, 종료, 단일 인스턴스, 설정 조정 |
| `platform` | 파일, 경로, 시간, 감시, Windows 핸들 관리 |
| `providers` | 제공자 경로 탐색, 원본 파싱, 의미 정규화 |
| `usage` | 이벤트 중복 제거, 기간별 집계, 수집 상태 |
| `storage` | 설정, 이벤트 캐시, 체크포인트, 복구 |
| `ui` | 트레이, 요약창, 설정창 |

UI 스레드는 메시지와 표시만 담당한다. 초기에는 수집 작업 스레드 1개를 사용해 상태 변경을 직렬화하고, 결과를 스냅샷으로 UI에 전달한다. 종료 시 작업을 취소하고 완료를 기다려 핸들과 데이터를 정리한다.

제공자 인터페이스는 최소한 `Discover`, `ReadChanges`, `GetCapabilities` 역할을 제공한다. 한도 지원 여부와 토큰 필드 지원 여부를 능력 정보로 반환하여 UI가 제공자 이름에 따라 분기하지 않게 한다.

## 7. 데이터 수집과 저장

### 제공자 사전 검증

| 제공자 | 1차 조사 대상 | 확인해야 할 사항 |
| --- | --- | --- |
| Claude Code | 사용자 로컬 세션 기록 및 공식 로컬 출력 기능 | 실제 경로, 버전, 토큰 필드, 이벤트 식별자, 중복 기록 여부 |
| Codex | 사용자 로컬 세션 기록 및 사용량 이벤트 | 실제 경로, 버전, 누적값과 증가량의 차이, 세션 재개 시 동작 |

위 항목은 조사 계획이며 확정된 데이터 계약이 아니다. 구현 전에 익명화한 샘플로 기대 집계값을 정하고, 검증한 도구 버전과 형식을 문서화한다. WSL 내부나 원격 PC의 기록은 초기 자동 탐색 대상에서 제외한다.

### 최소 공통 데이터

| 데이터 | 필드 예시 |
| --- | --- |
| 사용량 이벤트 | 제공자, 원본 식별자, 이벤트 키, UTC 시각, 모델, 입력·출력·캐시 토큰 |
| 수집 상태 | 마지막 시도·성공 시각, 상태 코드, 수집 범위, 형식 버전 |
| 파일 체크포인트 | 원본 파일 식별자, 읽기 오프셋, 수정 시각, 파서 버전 |
| 향후 한도 정보 | 제공자, 계정 범위 식별자, 대상, 기간, 사용 비율, 초기화·측정 시각, 출처 |

없는 토큰 필드는 선택 값으로 보관하고, 숫자는 64비트 정수와 범위 검증을 사용한다. 계정 식별이 불가능한 로컬 데이터는 계정별 사용량으로 표시하지 않는다.

### 증분 수집의 정확성

- JSONL은 완결된 줄까지 처리하고 아직 쓰는 중인 마지막 줄은 다음 읽기로 넘긴다.
- 파일 잠금이나 일시적인 읽기 실패는 재시도하며 기존 집계를 삭제하지 않는다.
- 파일 축소, 교체, 회전은 파일 식별자와 크기 변화로 감지한다.
- 파일 오프셋 외에 제공자 이벤트 키를 이용하여 재탐색·세션 재개 시 중복을 제거한다.
- 동일 이벤트 키에 값이 수정되면 기존 값을 대체하고 집계를 보정한다.
- 누적 카운터는 제공자별 규칙으로 증가량으로 변환한다. 단순 합산하지 않는다.
- 원본마다 증가량과 누적값 중 어떤 표현을 채택할지 정해 같은 사용량을 두 번 반영하지 않는다.
- 감시 이벤트는 작업 힌트로 사용한다. 버퍼 넘침 또는 오류 시 재탐색으로 복구한다.
- 기본 10초 갱신 주기와 60초 메타데이터 재확인을 시작값으로 두고 성능 측정 후 조정한다.
- 첫 실행의 큰 기록은 나누어 읽고 진행 상태를 표시한다. UI 스레드에서 전체 파일을 읽지 않는다.

### 로컬 저장 정책

기본 경로는 `%LOCALAPPDATA%\AI Mon\`으로 한다. EXE 위치에 쓰기 권한이 없어도 실행할 수 있게 한다.

- `settings.json`: 활성 제공자, 경로, 갱신 주기, UI 설정.
- `usage-cache.jsonl`: 대화 본문을 제외한 정규화 이벤트. 초기 보존 기간 7일, 최대 10MB 목표.
- `checkpoint.json`: 원본별 읽기 위치와 캐시 세대 식별자.
- `diagnostics.log`: 오류 코드와 상태 중심의 제한된 진단 기록. 최대 1MB.

집계는 제한된 이벤트 캐시에서 재구성한다. 캐시와 체크포인트는 세대 일치 여부를 확인하고 불일치하면 원본에서 재생한다. 캐시를 먼저 내구성 있게 기록하고 체크포인트를 갱신하며, 재생된 이벤트는 중복 제거한다.

원본과 캐시 모두에서 사라진 기록은 복구할 수 없다. 손상이나 용량 제한으로 수집 범위가 줄면 상태에 표시한다. 데이터 파일은 저장 형식 버전을 가지며 해석할 수 없는 캐시는 안전하게 재생성한다.

사용자가 수집 경로를 바꾸면 기존 범위의 합계를 새 범위와 묵시적으로 합치지 않고 현재 선택 범위로 다시 구성한다.

## 8. 1MB 배포 전략

1MB 이하는 현재 측정 결과가 아니라 제품의 통과 조건이다. C++ 지원 라이브러리의 링크 방식과 파서 선택이 영향을 주므로 기능 개발 전에 최소 앱으로 확인한다.

1. Windows 시스템 DLL을 활용하고 비시스템 런타임 DLL은 요구하지 않는다.
2. C++ 지원 라이브러리는 필요한 부분이 실행 파일에 포함되도록 구성하고 실제 DLL 의존성을 검사한다.
3. 크기 최적화, LTO, 미사용 코드 제거를 비교하여 Release 구성을 고정한다.
4. 디버그 정보는 별도 개발 산출물로 보관한다.
5. 시스템 폰트와 소형 아이콘을 사용한다.
6. 새 의존성은 적용 전후 Release 크기를 비교한다.
7. 실행 파일 압축 도구에 의존하지 않고 목표를 달성한다.

| 기준 | 대응 |
| --- | --- |
| 800,000바이트 이하 | 기능 개발을 위한 내부 목표 |
| 800,000바이트 초과 | 코드·리소스·링크 크기 분석 및 여유 재산정 |
| 1,000,000바이트 초과 | 배포 검사 실패 |
| 비시스템 DLL 필요 | 단일 EXE 배포 검사 실패 |

크기 초과 시 먼저 포함된 라이브러리와 리소스를 분석하고, 다음으로 빌드 설정을 조정한다. 필수 기능이 목표 안에 들어오지 않으면 원인과 측정치를 기록하고 범위 또는 구현 대안을 검토한다.

## 9. 성능과 운영 목표

아래 수치는 초기 검증 목표이며, 달성한 성능을 의미하지 않는다.

| 항목 | 목표 및 측정 조건 |
| --- | --- |
| 트레이 표시 | 로컬 SSD 환경에서 실행 후 1초 이내; 초기 인덱싱과 분리 |
| 유휴 CPU | 초기 수집 완료·새 기록 없음 상태에서 5분 평균 0.1% 이하, 전체 CPU 기준 |
| 유휴 메모리 | 요약창 숨김 상태의 Private Bytes 30MB 이하 |
| UI 응답 | 수집 중 열기·닫기·메뉴 입력이 눈에 띄게 멈추지 않음 |
| 갱신 지연 | 일반적인 작은 로그 추가 후 기본 설정에서 15초 이내 반영 |
| 로그 I/O | 변경 없는 상태에서 로그 본문 전체 재읽기 없음 |
| 장시간 실행 | 24시간 실행에서 메모리 및 GDI·커널 핸들의 지속 증가 없음 |

실제 측정 시 CPU 모델, RAM, OS 빌드, 로그 크기·개수와 측정 도구를 기록한다. 대규모 초기 수집 성능은 유휴 성능과 별도로 측정한다.

## 10. 검증 계획

### 자동 검증

- 제공자별 익명화 샘플과 수동 산정한 기대 사용량 비교.
- 동일 요청 중복, 세션 재개, 누적 카운터, 수정 이벤트 처리.
- 부분 줄, 잘못된 JSON, 큰 레코드, 잘못된 숫자 및 알려지지 않은 필드 처리.
- 파일 회전·축소·교체 및 감시 누락 후 재탐색.
- 자정 경계, 시간대 변경 및 데이터 없음과 0의 구분.
- 캐시 기록 중 중단, 체크포인트 불일치, 재시작 후 집계 동일성.
- Release 크기와 DLL 의존성 검사.

테스트 실행 파일은 제품 EXE와 분리한다. 파서와 집계의 입력·출력 검증을 우선하고 무거운 테스트 프레임워크는 필수로 두지 않는다.

### 실제 Windows 검증

- 개발도구와 추가 런타임이 없는 Windows 10/11 x64 환경에서 실행.
- 일반 사용자 권한 및 한글·공백이 포함된 사용자 경로.
- 트레이 클릭, 키보드 탐색, 고대비, DPI 배율, 다중 모니터.
- Explorer 재시작, 절전 복귀, 앱 중복 실행 및 정상 종료.
- 경로 없음, 권한 거부, 로그 기록 중 읽기, 큰 로그의 최초 수집.
- 24시간 실행과 데이터 수집량 증가에 따른 자원 변화.

## 11. 개발 단계와 완료 조건

| 단계 | 작업 | 산출물 및 통과 조건 |
| --- | --- | --- |
| 0. 기술 검증 | 포터블 도구 구성, 최소 C++ 트레이 앱, 파서·링크 비교, 제공자 샘플 조사 | 단일 EXE 실행·크기·의존성 측정, 디버깅 확인, OS 최소 빌드와 입력 계약 기록 |
| 1. 앱 골격 | 단일 인스턴스, 트레이, 요약창, 설정, 종료 처리 | 실제 Windows UI 확인, 일반 권한 실행, 설정 재시작 유지 |
| 2. 첫 제공자 | 샘플 접근이 쉬운 제공자 1개, 사용량 정규화·집계 | 샘플 기대값 일치, 중복·부분 기록·재시작 검증 통과 |
| 3. 두 번째 제공자 | 나머지 제공자, 공통 인터페이스와 증분 감시 | 두 제공자 동시 표시, 한쪽 오류가 다른 수집을 막지 않음 |
| 4. MVP 마감 | 캐시 복구, DPI, 상태 표시, 성능 및 배포 검사 | 필수 기능 완료, 1MB 이하, 추가 런타임 없는 환경에서 실행 |
| 5. 후속 확장 | 한도, 비용 추정, 기간별 통계, 알림 | 기능별 데이터 출처·정확도·크기 검증 후 순차 도입 |

0단계가 완료되기 전에는 개발 일정을 확정하지 않는다. 특히 제공자 형식 검증, C++ 링크 크기, 회사 PC의 도구 실행 가능 여부가 후속 일정에 영향을 준다.

MVP 출시 조건은 4단계까지의 필수 기능과 검증 통과다. 서비스 잔여 한도는 별도 검증이 필요한 후속 기능이며 MVP에서 임의 값으로 채우지 않는다.
