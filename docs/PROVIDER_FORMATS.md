# 제공자 기록 형식과 집계 규칙

확인일: 2026-09-10. 이 PC에서 확인한 로컬 기록 구조와 익명화한 합성 샘플을 기준으로 구현했다.
특정 도구의 모든 버전에서 동일한 형식을 제공한다고 보장하지 않는다.
원본 프롬프트·응답·인증 정보는 테스트 소스에 포함하지 않았다.

## Claude Code

기본적으로 `.claude/projects` 하위의 JSONL을 읽는다. `CLAUDE_CONFIG_DIR`가 있으면 그 경로를 사용한다.

```json
{
  "type": "assistant",
  "sessionId": "example-session",
  "requestId": "example-request",
  "timestamp": "2026-09-10T01:00:00Z",
  "message": {
    "id": "example-message",
    "usage": {
      "input_tokens": 100,
      "output_tokens": 10,
      "cache_read_input_tokens": 20,
      "cache_creation_input_tokens": 5
    }
  }
}
```

- `assistant`의 `message.usage`만 사용한다.
- 입력 토큰은 `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`로 표시한다. 위 예시는 입력 125, 출력 10이다.
- 캐시 읽기와 쓰기는 입력에 포함된 내역으로 표시한다.
- 세션·요청·메시지 ID 조합으로 중복을 제거한다. 세션 ID가 없으면 원본 경로에서 파생한 식별자를 사용한다.
- 같은 메시지의 새로운 시각에 기록된 값은 이전 사용량을 보정한다. 오래된 사본이 최신 값을 덮어쓰지 않는다.
- 메시지가 처음 기록된 시각을 날짜 집계 기준으로 유지한다.
- 메시지 ID 또는 필수 입력·출력 필드가 없으면 지원하지 않는 형식으로 표시한다.
- `iterations`, `thinking_tokens`, 중첩된 캐시 상세를 기본 사용량에 추가 합산하지 않는다.

## Codex

기본적으로 `.codex/sessions` 하위의 JSONL을 읽는다. `CODEX_HOME`이 있으면 그 경로 아래 `sessions`를 사용한다.
기본 탐색은 `archived_sessions`나 WSL 내부까지 포함하지 않는다. 설정에서 단일 수집 루트를 변경할 수 있다.

```json
{
  "type": "event_msg",
  "timestamp": "2026-09-10T01:00:00Z",
  "payload": {
    "type": "token_count",
    "info": {
      "total_token_usage": {
        "input_tokens": 150,
        "output_tokens": 15,
        "cached_input_tokens": 50
      },
      "last_token_usage": {
        "input_tokens": 50,
        "output_tokens": 5,
        "cached_input_tokens": 10
      }
    }
  }
}
```

- `session_meta.payload.id`를 세션 식별자로 사용한다. 없으면 원본 경로 식별자로 대체한다.
- `event_msg` 중 `payload.type == token_count`만 사용한다. `info == null`인 이벤트는 토큰을 추가하지 않는다.
- 이전 누적 입력 100·출력 10 다음에 위 예시가 나오면 입력 50·출력 5만 더한다.
- 동일 누적값의 반복은 무시한다. 누적값이 감소하면 새 카운터 구간으로 처리한다.
- 파일의 첫 사용량이나 카운터 초기화 시 `last_token_usage`가 유효하면 그 요청만 반영한다. 없으면 첫 누적값을 사용한다.
- 캐시 읽기·쓰기는 입력에 포함된 값으로 취급한다. reasoning 출력은 출력에 다시 더하지 않는다.
- 세션 ID·카운터 구간·누적값 조합으로 같은 스냅샷을 중복 제거한다.

파일 중간부터 시작하는 로그, 다른 세션 ID로 복제한 대화, 임의 수정한 기록에서는 원래 요청을 완전히 재구성할 수 없다.
로컬 집계는 서비스 계정의 공식 과금·한도 값이 아니다.

## 공통 처리

- UTF-8 및 JSON 파싱을 검증한다. 중첩 깊이는 64, 한 레코드는 2MiB로 제한한다.
- 시간은 UTC 또는 명시적 오프셋이 있는 ISO 8601을 읽고 Windows 로컬 날짜로 집계한다.
- cJSON의 숫자 표현 범위를 고려해 필드별 정수는 0~9,007,199,254,740,991로 제한한다. 음수·소수·무한값은 거부한다.
- 완결된 줄까지만 체크포인트를 진행한다. 쓰는 중인 마지막 줄은 다음 읽기로 넘긴다.
- 너무 긴 줄은 줄 끝까지 건너뛰고 다음 기록에서 다시 시작한다. 제외된 기록이 있으면 부분 수집 상태로 표시한다.
- 파일 교체·축소와 수정 시 접두부 변화를 감지한다. 읽은 이벤트는 최근 7일 동안 캐시에 남긴다.
- 서로 다른 제공자의 실패는 분리한다. 실패한 제공자의 마지막 집계는 유지한다.

현재 부분 수집 상태는 파일 전체의 읽기 이력을 반영한다. 따라서 오늘과 무관한 오래된 대형 기록이 제외되어도 부분 수집으로 표시될 수 있다.

## 저장의 일관성

기획서의 캐시·체크포인트 두 파일 대신 하나의 `state.json`에 이벤트와 읽기 위치를 함께 기록한다.
임시 파일 기록과 flush 이후 파일을 교체하여 서로 다른 세대의 캐시와 체크포인트가 섞이는 경우를 없앴다.

저장 형식은 버전 1이다. 문서 전체 검증이 끝난 뒤 상태를 교체하며 손상된 상태의 일부만 적용하지 않는다.
최대 24,000개 이벤트, 20,000개 파일, 10MiB 상태 파일을 상한으로 사용한다. 한도에 도달하거나 캐시 기록에 실패하면 UI에 표시한다.
